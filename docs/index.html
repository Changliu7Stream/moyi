墨忆文档

墨忆是一个给 AI Agent 用的记忆中间件：Agent 把值得记住的话丢进来，它负责向量化、去重、按语义召回、随时间衰减。它本身不是 Agent，也不调用大模型 —— 它站在 Agent 和你的数据库之间。

这套文档怎么读

如果你只想跑起来，直接看十分钟跑通。 如果你卡在「我这个环境到底算哪种」，看环境自动识别—— 那页把代码里每一条判断都摊开了写。

它解决什么问题

大模型的上下文窗口是临时的。一次对话结束，Agent 就忘了你是谁、上次让它别做什么、你偏好在什么环境里写代码。墨忆把这部分「长期记忆」挪到数据库里，检索时再按需捞回来。

关键设计是每个 Agent 各有一套记忆。你的编程助手不该看见你日程助手的私人备忘。默认隔离，只有在管理台显式打开「全局记忆」时才跨 Agent 可见，且只放宽读、不放宽写（详见Agent 与全局记忆）。

部件构成

sql/两套迁移脚本（自托管 / Supabase）同一套表结构，权限模型不同

一次请求的流向

理解这张图，后面所有部署差异都只是「中间那一跳换人」而已：

1Agent / 浏览器带 X-Moyi-Key（Agent）或会话 Cookie（管理台）发请求
→
2墨忆服务认证、限速、业务规则、向量生成、读写权限裁剪
→
3PostgREST把 REST 查询翻译成 SQL；它是唯一的存储出口
→
4PostgreSQL + pgvector存数据；HNSW 索引做近邻召回

第 3 步是关键：墨忆不认识「数据库」，只认识「PostgREST 协议的 HTTP 接口」。所以自托管的 PostgREST 和 Supabase 托管的 PostgREST 可以互换，代码一行不改。这就是 环境自动识别 那页存在的理由——两种后端的差异全在 URL 形态和路径前缀上。

两套认证面，互不通用

这是 v3.3 起最容易搞混的地方，先在这里钉住：

Agent 面控制台面
路径前缀/api/*/api/console/*
凭据X-Moyi-Key: moyi_xxx用户名+口令 → 会话 Cookie
口令/密钥存储API Key 的 sha256scrypt 哈希（自描述格式）
谁在用各个 Agent 程序、MCP 客户端人，在浏览器里
能读记忆正文？只能读自己那套读不到任何记忆正文
跨面生效？不能。管理员 Cookie 打 /api/memories 回 401，反之亦然

「管理员看不见记忆正文」是刻意的：管理员是管工具的人，不是读别人日记的人。要读某个 Agent 的记忆，得拿那个 Agent 自己的 Key。

三种部署形态

连外部 Supabase只管墨忆一个容器/进程，数据库托管。上手最快。 自托管全栈Postgres + PostgREST + 墨忆三个容器，数据完全在自己手里。 Vercel Serverless免运维，但限速与审计退化为「每实例独立」。适合个人低频用。

硬性前提

数据库连接信息只能用环境变量配

管理台里没有填数据库地址的地方，这不是没做完。如果网页能配后端地址，那么任何一次 XSS 都具备把整个实例的后端换成攻击者服务器能力——口令、会话、全部记忆都会流过去。所以这条缝留在文件系统里，不留给浏览器。

另两个前提在HTTPS 与反向代理里细说：PostgREST 绝不暴露公网、反向代理必须正确传 X-Forwarded-Proto。

边界：它做不到什么

与其列待办，不如把做不到的写清楚：

  • 不接 embedding provider 时，「语义检索」名不副实。默认是本地特征哈希，近义词召回明显偏弱。去重也因此不能只信向量。
  • 衰减永不自动删除。would_forget 只是一份候选清单，要真删得逐条发 DELETE。
  • 审计日志在进程内存里，重启即失、多实例不共享，不能当合规留痕。
  • 图谱是共现图，不是语义图。边权重不宜作为推理依据。
  • 没有自助找回口令的通道。忘了口令只能手工改库，这是取舍而非遗漏（见对照页）。
