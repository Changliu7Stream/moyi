引导安装与管理台

管理台是给部署者用的，不是给 Agent 用的。它管三件事：发钥匙（Agent）、管人（管理员）、开关（实例设置）。它看不见任何一条记忆的正文——这是刻意的。

1跑迁移 SQL建出 agents / memories / admins / admin_sessions / settings 五张表
→
2配环境变量存储 URL + token（这步不能省，也不能在网页里填）
→
3访问 /console自动进入引导安装页，填用户名口令
→
4装完即封存引导页永久消失，此后只能登录

引导安装页：一次性的，装完就没了

首次访问 http://<你的地址>:3906/console，如果服务端判定这是台干净的新实例，页面会直接变成安装向导：填管理员用户名与口令，可选填实例显示名、是否开放公开注册。确认提交后，这个入口永久关闭。

「是否已安装」由服务端说了算

页面本身不做判断，每次渲染都先请求公开的 GET /api/console/status。判定式是四个条件的与：

needs_setup = !admins表缺失 && !settings表缺失 && 无管理员 && 未落锁

所以「换个浏览器 / 清 Cookie / 改前端变量」都没法把安装页重新叫出来。想再看到安装页，只有一条路：把库清空——而这在任何已投产实例上都是自杀式操作。完整的状态字段真值表在环境自动识别那页。

为什么要做「一次性」而不是留个安装页备用

公开的「创建第一个超管」表单是互联网上最常见的靶子：任何人抢先提交一次，就把整台机器变成了他的。把它设计成装完即封存，等于在时间轴上消灭了这个攻击面——窗口只在部署后的那几分钟存在。

并发安装只有一个能赢

假设两个人同时打开安装页并都点了提交。落锁靠往 settings 插一行 setup_locked（该表以 key 为主键），PostgREST 在主键冲突时回 409——这个 409 就是 CAS 的「抢锁失败」。输的一方会删掉自己刚建的管理员，然后回 409「本实例刚刚已被安装」。所以绝不会留下两个首任超管，也不会留下「建了管理员但没落锁」的中间态。

你勾的选项会真的生效

迁移 SQL 会预插 instance_name、open_register 等行，所以安装时写选项用的是「先 PATCH，命中 0 行再 merge-duplicates 补插」的 upsert。用裸 POST 的后果是撞主键 409、又因 return=minimal 没人检查状态码，症状非常阴险：你在安装页关掉了公开注册，装完发现它还是开着的。

登录与安全模型

环节实现为什么
口令存储scrypt，N=16384 / r=8 / p=1 / keylen=32，自描述格式 scrypt$N$r$p$salt$hash参数写进哈希里，日后调参也不影响旧口令校验；服务端无法还原明文
口令强度≥10 字符、≤512、拒绝单字符重复、拒绝 6 个极常见口令只做下限拦截，不搞复杂度恐吓
用户名2–32 字符，字母数字 _ - 或中文，自动 trim允许中文管理员名
会话 token32 字节随机 → base64url；库里只存它的 sha256拖库拿不到可用的会话凭据
CookieHttpOnly; SameSite=Strict; Path=/; Max-Age=…，且仅当 X-Forwarded-Proto: https 时追加 Secure见反向代理页
整账号踢下线admins.session_version 计数；改口令 / 被停用 / 改角色都会 +1不需要维护「撤销列表」，一次更新作废全部旧会话
CSRF双层：SameSite=Strict + 所有非 GET 的控制台写请求必须带 X-Moyi-Console: 1跨站表单无法设置自定义头，缺头即 403——即使你已登录
口令暴破每来源 15 分钟 10 次失败（MOYI_ADMIN_FAIL_PER_15MIN），与 Agent Key 的计数器完全分开某台机器在试 Agent Key，不该顺手把你锁在管理台外面

登录失败时，「用户名不存在」和「口令错误」回完全相同的提示与状态码（401），不给用户名枚举留缝。

注意：口令策略只挡「离谱」，不挡「不够强」

它不查字典、不要求字符类别混合，password123 这类变体是能过的（弱口令清单是精确匹配，不是包含匹配）。管理员口令是整台实例的门，请自己选一条足够长的、独一无二的口令——比如 20 个随机字符。

四个页签

Agent（发号与除名）

这里建的每个 Agent 都是独立钥匙、独立记忆。点「创建并取钥」后一次性拿到 API Key 和一段可直接粘贴的 MCP 配置：

{
  "mcpServers": {
    "moyi": {
      "command": "node",
      "args": ["/absolute/path/to/moyi/mcp-server.js"],
      "env": { "MOYI_API": "http://localhost:3906", "MOYI_KEY": "moyi_…" }
    }
  }
}

Key 只在创建和轮换时出现一次

库里存的是它的 sha256，没有可逆存储，管理台之后再也读不出来。丢了就点「重置 Key」——旧 Key 立刻失效，那份旧 MCP 配置随之作废。请把新 Key 直接贴进客户端配置，别截图、别贴进聊天工具。

列表只显示每个 Agent 的条数（high / medium / low 与已同步数），不显示内容。这一页看不到别人记了什么。

另外一处硬限制：通过管理台建的 Agent 一律是 role='agent'。即便请求体里塞了 role: 'master' 也会被服务端覆盖掉——否则「Agent 身份」就成了通往更大权限的跳板，master 能读审计、能回填别人的向量。

管理员（管人）

仅超管可见。两种角色：super 能管人和改设置，admin 只能管自己的会话与口令。护栏是四条：

  • 不能停用自己；不能改自己的角色（防止把自己降完就升不回来）；不能删自己
  • 系统里至少留一个可用超管——仍有其它超管时，停用/降级/删除某个超管是允许的
  • 停用会立刻作废该账号全部会话；恢复后需重新登录
  • 超管给别人重置口令时，看不到旧口令，只能设新口令

注意管理员与 Agent 是两个独立的表、两个独立的概念，不是同一套账号的不同权限级别。管理员不能用 Cookie 调 Agent 接口，Agent 也不能用 Key 登管理台。

会话

看这台实例上现在有哪些登录态，可单条撤销。超管能看全部管理员的会话，普通管理员只能看自己的。列表里恰好一条会标 current（就是你正在用的这条）——它比对的是会话行本身的 id，不是账号 id，所以同一账号多设备不会全部被标成本次。

设置

三项，写在 settings 表里，改完即生效（最迟延迟见下）：

设置效果谁能改
实例显示名前端标题，最长 40 字符（超出截断）超管
开放公开注册关掉后 POST /api/agents/register 回 403，只能由管理台或 master 发号。但带正确 master_code 的请求仍然放行——否则关掉注册会连自己人一起锁在门外超管
全局记忆跨 Agent 只读可见，详见下一节超管

可写键是白名单硬编码的，白名单外的键会被静默忽略，尤其 setup_locked 绝不能从设置接口写——不然就等于留了个「把自己重新变回未安装」的后门。

改设置到全实例生效，最慢 MOYI_SETTINGS_TTL_MS（默认 5000 毫秒）

设置读一遍会缓存在进程内 5 秒。同进程里自己改自己立即生效（写入即失效缓存）；多实例部署（Vercel、或 Docker 副本数 >1）才会有这个几秒窗口。要彻底没有延迟就设 0，代价是每个请求多一次 settings 查询。

忘记管理员口令：只能手工改库

没有「忘记密码」按钮，这是有意的。自助找回需要一条对外通道（邮箱、短信、安全问题），每一条都是新的攻击面；而这个系统里一个超管口令就等于全库记忆，所以宁可麻烦运维，也不给攻击者多开一个入口。

恢复步骤（需直连数据库）：

# 1) 用同库代码里的同一套算法生成新哈希
node -e "const c=require('./lib/console.js');c.hashPassword('新口令').then(console.log)"

# 2) 写回该行，并把 session_version 加一
UPDATE public.admins
   SET password_hash = '<上一步输出>',
       session_version = <当前值 + 1>,
       disabled = false
 WHERE username = '你的管理员名';

session_version 必须 +1：新口令生效的同时把该账号所有旧会话作废。否则那个哈希包在拖库场景里被破解后，攻击者手里的旧 Cookie 会一直好用到自然过期。

如果整个实例连一个可用超管都不剩（比如误删了全部管理员），先手工插一行 role='super' 的管理员再登录。不要去删 settings 里的 setup_locked 来「重开安装页」——那等于把公开的超管创建入口重新打开，任何能访问该地址的人都可以给自己造一个超管。

哪些东西必须留在环境变量里

管理台不能配置数据库连接，也不能改 embedding provider 的地址与密钥。理由见环境变量页开头那条铁律：如果网页能改后端地址，任何一次 XSS 都能把整台实例的记忆流去攻击者的库——口令、会话、全部数据一起走。把这条缝留在文件系统里，浏览器碰不到。

一句话原则

引导页只在部署的那几分钟存在；管理台日常只做发钥匙、管人、开开关三件事；记忆的正文永远只属于拿着那把 Agent Key 的人。
