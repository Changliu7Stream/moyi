底层 / Account Gaps

对照：网站账号体系

这一页来自一份典型的需求清单：适配 PC/H5 网站、可直接运行、无安全漏洞、符合网站合规要求的账号注册登录功能完整方案——注册、密码+验证码登录、忘记密码、信息修改、注销、登录日志、第三方登录，外加 bcrypt、5 次失败锁 30 分钟、IP 超频拉黑、HTTPS 强制、Secure+HttpOnly Cookie、CORS 只放行自己、脱敏存储、SQL 注入/XSS/CSRF 防护。

墨忆不是网站用户系统，它有两套完全不同的身份面，先钉住这个前提：

Agent 面（机器）管理面（人）
入口POST /api/agents/register 领 Key浏览器 /console.html 登口令
凭据X-Moyi-Key: moyi_xxx（长期有效）用户名+口令 → 短期会话 Cookie
对应清单里的「注册发号」这一半「账号登录」这一整半
有个人身份信息？只有 name（≤64 字）只有 username（2–32 字）

所以下面的对照全部针对管理面。清单里那些「手机号、邮箱、图形验证码、第三方授权登录」的条目，在墨忆里没有对应物——不是因为漏了，而是因为它压根不采集这些信息。

一、怎么读这一页

每个条目打一个标签：

标签含义
已有清单要的东西墨忆有，实现方式可能和清单写的不一样
换了做法目标一致，机制或数值不同；差异会写清楚为什么
刻意不做能做但主动不做，理由比实现更重要
真没有缺，而且做这行的人应该知道它缺

三条贯穿全文的设计前提，理解了它们，大部分取舍就自解释了：

零依赖整仓库没有一个 npm 生产依赖。bcrypt、邮件 SDK、短信 SDK、OAuth 库、验证码服务全部进不来。
只信任反代墨忆只听 HTTP，TLS、真实 IP、协议判定全交给反向代理。凡是「网络层该管的」它不管。
无状态优先要能在 Vercel 这类实例随时回收的环境跑。所以落盘的留痕、内存态的计数器都会诚实标注边界。

二、账号生命周期对照

清单里七个环节，逐个对上：

清单要求状态墨忆现状
注册刻意不做管理员不能自助注册。账号只有两个来源：引导安装页建的第一位超管，和超管在 POST /api/console/admins 手工创建（lib/moyi.js:870）。一个能公开注册的后台账号系统，等于把「谁来管这台机器」交给互联网。清单里的「注册」在墨忆侧另有对应物——Agent 公开注册 /api/agents/register，它有 IP 限速、也可以整体关掉，见第四节。
密码登录已有POST /api/console/login（lib/moyi.js:759）。用户名不存在与口令错误回同一句话同一状态码（401「用户名或密码不正确」），挡住用户名枚举。
验证码登录真没有没有短信/邮箱验证码登录通道，也没有图形验证码。见第七节的补法。
忘记密码刻意不做没有自助找回。忘了口令只有两条路：另一位超管 POST /api/console/admins/:id/password 重置，或进数据库手工改（管理台 那页有完整命令）。理由：任何「能远程改掉管理员口令」的接口本身就是这个系统最大的攻击面。
信息修改换了做法能改的只有 disabled 与 role，且仅超管（PATCH /api/console/admins/:id，lib/moyi.js:907）；本人能改的只有自己的口令（POST /me/password，需带当前口令）。没有昵称、头像、邮箱、手机号可改——库里就没这些列。
注销换了做法硬删除：DELETE /api/console/admins/:id，仅超管、不能删自己、必须至少留一个可用超管（lib/moyi.js:933），会话一并清掉。清单通常要求的「用户自助注销 + 软删除 + 冷静期 + 留存期匿名化」没有。
登录日志真没有有事件、但不成日志：console.login / login_failed / login_disabled / logout / password_changed / session_revoked / admin_* 全都写进进程内存的环形缓冲，重启即失，且不记 IP 和 UA。详见第五节。
第三方登录真没有只有用户名+口令。没有 OAuth/OIDC 接入点，也没有可扩展的 provider 抽象——加一个就等于引入一个外部依赖链。

三、数据库对照

清单的「数据库设计」模块通常长这样，和墨忆实际的 sql/00-schema.sql 逐列比：

典型字段墨忆说明
用户 ID有admins.id uuid PRIMARY KEY DEFAULT gen_random_uuid()
用户名有username text NOT NULL UNIQUE
口令哈希有password_hash，格式 scrypt$N$r$p$salt$hash，参数随哈希一起存（换参数不必重算全库）
角色 / 权限有role CHECK (role IN ('super','admin'))，两档够用
启用状态有disabled boolean，停用即踢全部会话
会话吊销版本有session_version bigint——这是清单里通常没有、但「改密码全端下线」必须依赖的一列
注册时间有created_at
邮箱 / 手机号无不采集。连带后果：清单里的「敏感信息脱敏存储」在墨忆没有适用对象——唯一的个人信息就是一个用户名，而它必须以原样存才能登录时比对。
最后登录时间 / IP无没有这一列，也没有地方写。要做「异常登录提醒」先得有它
软删除 / 注销时间无删除就是 DELETE；admin_sessions 靠 ON DELETE CASCADE 一起走
验证码 / 找回 token 表无没有自助找回，自然没有承载一次性 token 的表
登录历史表无会话表只存当前有效的会话，用过即废的会被顺手删掉（lib/moyi.js:234-237），它不是历史表
IP 黑名单表无限速是内存滑动窗口，重启清零；持久封禁归反代/防火墙

为什么 admins 不并进 agents

Agent 是「工具」，持 API Key 走 MCP；管理员是「人」，持口令登面板。混在一张表里只靠 role 区分，迟早写出「某个 Agent 的 key 能登管理面板」这类越权。这条注释就在 sql/00-schema.sql:63 上方——如果清单的实现者把两种身份塞进一张 users 表，那是同一类漏洞的入口。

四、后端对照

先看另一套：Agent 面的注册与换钥

清单里「注册 → 发凭据 → 换凭据 → 注销」这条链，在墨忆的 Agent 面其实有完整对应物，而且它是唯一允许公开注册的那一面：

环节状态实现
公开注册已有POST /api/agents/register：只给 name（≤64 字），返回一次性明文 Key，库里只存 sha256(key)
注册防滥用已有每来源 1 小时 10 次 / 1 天 30 次（MOYI_REGISTER_PER_HOUR / _PER_DAY），实例可在设置里关掉自助注册（open_register=0），关掉后仍保留带 MOYI_CODE 的通道，避免把自己锁在门外
换钥（等价于改密）已有POST /api/agents/:id/reset-key，仅 master；旧 Key 立即失效，新 Key 只回一次（lib/moyi.js:1213-1222）。日志只记「谁给谁换了钥匙」，密钥本身绝不进日志
注销只有硬删master 或超管 DELETE /agents/:id，连带抹掉该 Agent 全部记忆，不可自助、不可撤销、无冷静期。清单要的「用户自己点注销、数据保留期内可撤回」没有

换句话说：Agent 面缺的不是功能，是「面向终端用户的自助性」——它的每一次凭据变更都要求一个更高权限的主体来执行。这正是它和管理面共享的设计取向。

口令哈希：清单要 bcrypt，墨忆用 scrypt

换了做法 目标是同一个：带盐、可调代价、验签恒定时间。墨忆用 Node 内置 crypto.scrypt（lib/console.js:26-46），参数 N=16384 / r=8 / p=1 / keylen=32，和 OWASP 给的 scrypt 下限一致，抗 GPU 的能力不逊于 bcrypt（bcrypt 只抗时间代价，内存硬度和 scrypt 不是一个量级）。两个必须知道的实现细节：

  • maxmem 必须显式放宽，否则 N=16384 在 Node 默认上限下直接抛错（lib/console.js:30,36）。
  • timingSafeEqual 前要对齐长度：两个 Buffer 长度不同会抛，直接 return false 又把「哈希长度」变成可计时区分的分支。代码先补齐或截断到同长再比（lib/console.js:66-74）。

换成 bcrypt 唯一的好处是格式更通用、跨语言工具多；代价是引入一个原生或纯 JS 依赖，零依赖前提就没了。

口令策略：长度 + 黑名单，不校验「复杂度」

换了做法 checkPasswordPolicy（lib/console.js:78-85）只有四条：≥10 字符、≤512 字符、不能是同一字符重复、不能等于弱口令表里的某一项（整串精确匹配，不分大小写）。没有「必须包含大小写数字符号」这类规则——研究表明那套规则产出的口令并没有更强，反而催生出 Password@2024 这种模板。诚实说一句：password123 能过这道闸门，因为长度够且不在弱口令表里。

校验只在服务端

口令策略、用户名格式（^[A-Za-z0-9_\-\u4e00-\u9fa5]{2,32}$，lib/console.js:87-90）全部在服务端执行。前端不做实时校验，也没有 required / pattern 属性——客户端校验能绕过，写了只会造成两套规则跑偏。清单要求「前端实时校验」的话，这是明确未满足项，补的时候也必须保留服务端这套为唯一真相。

认证方案：Session + Cookie（清单给的选项之一）

已有 清单在「JWT 双令牌 / Session+Cookie」之间让实现者选，墨忆选后者，理由只有一个但很硬：要能即时吊销。JWT 做不到「改口令后其它设备立刻下线」，除非再建一张吊销表——那就等于把会话状态又存回数据库，还多了一套签名密钥要管。现有实现：

1发令牌randomBytes(32).base64url，不透明、不自带任何声明（lib/console.js:100）
→
2只存哈希库里存 sha256(token)；数据库被整库读走也没法拿来登录
→
3版本比对admins.session_version 与 admin_sessions.session_version 不一致即作废
→
4过期即删用到已过期的行顺手 DELETE，不需要定时任务

Cookie 属性（lib/console.js:146-155）：

moyi_session=<token>; Path=/; HttpOnly; SameSite=Lax; Max-Age=<秒>[; Secure]

清单要的 HttpOnly ✓、Secure 有条件 ✓。Secure 只在 X-Forwarded-Proto 第一段是 https 时才加——墨忆不听 TLS，只能信反代传进来的头，配错的后果和自查方法在 HTTPS 与反向代理。

有效期是固定窗口，不滑动续期：sessionExpiresAt = now + SESSION_TTL_MS（lib/console.js:95-98 钳制、:106 计算到期），默认 7 天，钳制在 1 分钟 ~ 30 天。会话表 admin_sessions 只存当前有效的会话（token_hash UNIQUE + expires_at），用到已过期的行顺手删掉，所以它不需要定时清理任务，也不是登录历史表。

失败锁定：机制一致，数值不同

换了做法 清单要「连续 5 次失败锁 30 分钟」。墨忆是15 分钟内 10 次失败就回 429（MOYI_ADMIN_FAIL_PER_15MIN，默认 10，lib/moyi.js:251），想改成 5 次/更久直接调环境变量。更重要的是三条清单没提、但决定这个机制能不能用的细节：

  • 只统计失败，成功一次就清零（lib/audit.js:149-171）。早期版本把成功请求也计入，结果正常用户半小时被自己锁在门外。
  • 三套独立键空间：注册 reg:h: / reg:d:，Agent key 穷举 auth:，管理台口令 adminauth:。同一个计数器管所有，一个人试错能把全场锁掉。
  • 键是哈希过的：sha256(XFF 第一跳 || socketIP) 前 16 位（lib/audit.js:125-131），内存里不留明文 IP。

IP 超频拉黑：没有

真没有 清单要「单 IP 每分钟 >10 次请求 → 拉黑 1 小时」。墨忆只有滑动窗口限流，没有封禁状态，且窗口在内存里，实例重启就清零。这是有意的分工：可靠封禁要在反代或防火墙层做（nginx limit_req + limit_req_status 429，或 fail2ban），应用层做封禁在 serverless 上必然失真。

通知渠道：一个都不接

刻意不做 清单要「异地登录 / 改密 / 注册发信或短信提醒」。墨忆不发任何邮件或短信——两者都需要外部服务和密钥，而密钥一进来就撞上「环境变量之外的凭据往哪放」这个问题。现有替代是管理台会话页：超管能列出该实例全部有效会话（普通管理员只看自己的，lib/moyi.js:955），发现不认识的设备直接 DELETE /api/console/sessions/:id 撤销；改口令本身就会把旧会话全部作废。

越权与注入：清单的三项防线

要求状态实现
SQL 注入已有没有一处拼 SQL——查询是拼 PostgREST 的 URL 串。风险因此变成「查询串注入」，挡法是入参白名单：safeUuid / safeId / IMPORTANCE 集合（lib/moyi.js:270-279），格式不过就 400，用户名为 encodeURIComponent
XSS已有库里存的一直是原文，输出时转义——从不做「入库前过滤标签」那种两头不靠的做法。管理台 esc() 覆盖 & < > " '（public/console.js:19），另有 7 处直接赋 textContent（天然免转义，Key 与 MCP 配置片段这类要整段复制的字段走这条）。这套机制的脆弱点在第五节写明了
CSRF已有两层独立：SameSite=Lax + 写操作必须带 X-Moyi-Console: 1（lib/moyi.js:633-638）。跨站 <form> 发不出自定义头，跨站 fetch 想发就先过 CORS 预检
越权访问已有管理员改口令只能改自己（要验当前口令）；改别人、删别人、撤销别人会话一律要超管；不能停用或降级自己；不能删掉最后一个超管

两项清单会要求、墨忆确实没有的响应头

Content-Security-Policy 与 X-Frame-Options：没有设置（全仓库无一处下发），HSTS 也没有。当前靠 SameSite=Lax + 无第三方脚本 + HttpOnly 兜住点击劫持与内联注入的主要路径，但这是「够用」而不是「合规」。要么在反代统一加头，要么在 server.js 的响应封装里补——加之前先确认管理台没有内联脚本会被 CSP 打死。

HTTPS 与 CORS

HTTPS 强制 刻意不做：应用不听 TLS，不做 301 跳转，只从 X-Forwarded-Proto 读结论。清单里「强制 HTTPS」这一项在墨忆的部署形态下属于反代职责，配置见 HTTPS 与反向代理。

CORS 换了做法：白名单由 MOYI_ALLOWED_ORIGINS 显式列出（lib/moyi.js:575-585），不带 Origin 头的请求不返回 CORS 头——但 localhost:3906 与 127.0.0.1:3906 是无条件加进去的，方便本地开发。清单要求「CORS 只允许自己的域名」的话，这条要知道：127.0.0.1:3906 永远在允许列表里，任何监听本机 3906 的页面都能带着用户浏览器里的凭据打这个 API。公网实例应把墨忆绑到非本机可达的网卡，或改端口后确认这两条本机源无实际意义。设成 * 会回一个字面量 *，等于把整个 API 开放给任何网页，生产禁用。

五、前端对照

清单要求「适配 PC/H5，前端实时校验，防 XSS」。逐条对上管理台（public/console.html + public/console.js + public/console.css）：

要求状态墨忆现状
PC 端可用已有原生 JS 单页，无框架无构建产物；四个页签（概览 / Agent / 管理员 / 会话）+ 设置
H5 / 窄屏适配已有console.css 有 960px 与 720px 两档断点重排，登录与表单在手机上可填可提交。文档站另有一套（docs/assets/docs.css，≤1000px 抽屉式目录、≤600px 再压一档）
防 XSS（输出侧）够用但脆入库存原文、输出时转义，这是正确取向。但机制是「esc() 函数 + 调用点自觉」：全文 innerHTML 只有 4 处，插进去的动态行都先过 esc()；另有 7 处走 textContent（天然安全，Agent Key 一类要能整段复制的字段都走这条）。风险说清楚：4 处 innerHTML 里同时写着未转义的字面量（如 <p class="field-note">无在线会话。</p>）——目前安全，但将来谁把用户可控字符串塞进这类模板就破防
前端实时校验真没有表单没有 required / pattern 属性，console.js 里也没有长度判断。口令策略、用户名格式（^[A-Za-z0-9_\-\u4e00-\u9fa5]{2,32}$，lib/console.js:87-90）全在服务端跑，不合规就回 400 原话展示。这是取舍：客户端校验能绕过，写两套规则早晚跑偏。代价是提交前不给提示，体验差一档
记住我刻意不做会话已在服务端活 7 天（固定窗口，不滑动续期，lib/console.js:95-98,106），再做一个「延长版会话」只是多一条要审的分支
退出登录已有POST /api/console/logout：删会话行 + 下发 Max-Age=0 的空 Cookie（lib/moyi.js:794）

Cookie 属性（lib/console.js:146-155）

moyi_session=<token>; Path=/; HttpOnly; SameSite=Lax; Max-Age=<秒>[; Secure]

清单要的 HttpOnly ✓、Secure 有条件 ✓。Secure 只在 X-Forwarded-Proto 第一段是 https 时才加——墨忆不听 TLS，只能信反代传进来的头。配错的后果和自查方法见 HTTPS 与反向代理。

六、合规与留痕

如果这份清单是为了过等保或满足《网络安全法》的日志留存要求，下面这一项必须先补，而且要清楚现在缺的具体是什么：

合规日志通常需要墨忆
时间、事件类型有 {seq, ts, actor, action, detail}
来源 IP、设备 UA无 审计里根本没有这两个字段，采集处也没取
持久化、重启不丢无 进程内存环形缓冲，容量默认 2000 条，重启即失
多实例汇总无 每个实例各记各的
留存 ≥6 个月、日志本身不可篡改无 连一天都留不住

这不是疏忽，是取舍，而且代码主动承认：审计接口响应里固定带一句 warning——「实例重启或扩缩容后即失效；无状态部署下不可作为合规留痕」（lib/moyi.js:1402）。怕的就是有人把它当留痕用。

脱敏存储 换了做法：清单关心手机号、邮箱、身份证在库中和日志里的掩码。墨忆不采集这三样，所以「存储侧脱敏」没有适用对象——但同类问题以另一种形式存在，那就是凭据。审计事件写入前的规则（lib/audit.js:44-61）：键名命中 api_key|token|secret|password|master_code|authorization 一律替换成 «redacted»，值命中 moyi_[0-9a-f]{8,} 截断为 moyi_xxx…(redacted)。口令、Agent Key、会话 token 在任何日志与响应里都不出现原文。真要按清单落地一个网站账号系统，该抄的就是这一条：脱敏要发生在写入前的最后一道函数里，而不是指望调用方记得别传敏感字段。

七、如果真要补齐

按「补起来最不破坏现有设计」排序，前四项在零依赖下能自己做，后三项建议交给外部。

缺口补法代价
登录日志持久化新建 append-only 表 login_events(ts, actor, action, ip_hash, ua, ok)，在 audit() 旁边加一条 supa(…,'POST') 分支，内存环形缓冲保留做「最近事件」快查最小。一次写入、不改现有语义，是缺口里性价比最高的一项
IP / UA 采集上一条里的两列，取自现成的 clientKey(req)（哈希 IP）与 user-agent 头要新增 UA 截断（头可以很长），且必须明确不落明文 IP
软删除 + 冷静期admins 加 deleted_at，查询侧一律带 deleted_at=is.null，冷静期后由维护任务真删中等：needs_setup、超管兜底计数、会话列表都要跟着改，漏一处就出现「已注销账号还能登」
CSP / X-Frame-Options / HSTS反代统一加响应头（推荐），或在 server.js 的响应封装里补低，但要回归测管理台。文档站与 console.html 有内联脚本，CSP 写严了会直接白屏
图形验证码 / 滑块放反代或接 Cloudflare Turnstile 一类，应用层只在 adminAuthGate 之外多信一个头自建等于把「防机器人」这个无底洞揽进来；零依赖做不出真有效的
邮件 / 短信提醒与找回需要 SMTP/SMS 服务 + 凭据管理 + 一次性 token 表 + 限频 + 反滥用整条依赖链进来，且造出「远程改管理员口令」这个最大攻击面。墨忆选择不做，不是做不动
第三方 OAuth 登录需要 provider 抽象、state/nonce 校验、账号绑定表零依赖下要手写 PKCE 与 JWKS 校验，收益不抵风险；真要接建议放独立网关做 OIDC 反代

一句话总结

清单里的安全底线（口令哈希加盐恒定时间、会话即时吊销、HttpOnly/SameSite、CSRF、注入与越权、限速、凭据脱敏）墨忆都有，其中几项做法和清单写的不一样但目标更强。清单里的网站账号业务（自助注册、验证码、找回、通知、第三方登录、手机号邮箱）墨忆基本都没有——它管的是「谁能有资格操作这台机器」，不是「谁是我站上的用户」。真正需要在上线前补的只有两件事：持久化登录日志（含 IP/UA）和安全响应头。
