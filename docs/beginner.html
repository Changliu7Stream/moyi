部署前必看

这页假定你什么都没装、也没读过其它文档。目标是让你在动手前先建立三个正确认知：墨忆是个什么东西、你需要准备什么、数据库为什么只有一个选项。看完再回 十分钟跑通 照命令做，会顺很多。

一、墨忆到底是什么

墨忆（Moyi）是给 AI Agent 用的记忆服务：你的 Agent 通过一个 HTTP 接口（或 MCP 协议）往里写「记忆」，之后用语义检索把它捞回来。它自带一个管理台（网页，地址 /console）用来管 Agent、看审计、开关全局记忆。

对新手，你只要知道它由两部分组成就够开始：

  • 一个 Node 服务（server.js）——处理 API、跑管理台逻辑。零运行时依赖，不需要 npm install。
  • 一个数据库——存记忆、存 Agent、存管理员。墨忆不直连数据库，它通过 HTTP 打一个 PostgREST 接口（下一节解释）。

没有第三步。你不需要单独装 Redis、消息队列、向量数据库——那些能力墨忆要么内置、要么交给这一个数据库。

二、你需要准备什么

按你走哪条路，需要准备的东西不同。先对号入座：

你想怎么部署需要准备难度
Docker 自托管全栈（数据在自己手里）一台能跑 Docker 的机器（Linux/Mac/WSL）、docker + docker compose v2中
连托管 Supabase（不碰数据库）一个 Supabase 账号 + 项目；本机有 Docker 或 Node ≥ 18低
裸跑 Node 试一下本机 Node ≥ 18（其它什么都能先不管）最低

纯新手，建议先「裸跑 Node + Supabase」

Supabase 帮你把数据库、pgvector、HTTPS 全托管了，你只需配两个值（地址 + 密钥）。等你确认墨忆好用、要长期跑，再考虑自托管。十分钟跑通 · C 是最短路径。

三、数据库：只有一个选项，别找 MySQL

这是新手最容易白费功夫的地方。墨忆的存储后端只支持一种：PostgreSQL + pgvector 扩展。不支持 MySQL、SQLite、MongoDB、Cloudflare D1。原因很简单：记忆检索靠向量相似度，而墨忆用的向量能力来自 pgvector（Postgres 的扩展），建表脚本里就是 CREATE EXTENSION vector 和 vector(384) 列。换别的数据库等于换掉整套检索，不是配个连接串的事。

但「PostgreSQL + pgvector」有两种来源，对你完全等价——因为墨忆根本不连数据库，它连的是数据库前面的 PostgREST（一个把 Postgres 表暴露成 REST 接口的标准组件）：

Supabase 托管Supabase 底层就是 Postgres + PostgREST，开项目即用，无需自己运维。 自托管 PostgREST自己用 Docker 起 Postgres + PostgREST，数据完全在自己手里。

所以你可以这样记：「用 Supabase」和「用自托管 PostgREST」是同一个协议的两家实现，切换它俩不改一行代码。数据库细节在 数据库结构 和 数据库与环境支持 两页。

四、最少配哪几个变量

墨忆认的变量有 48 个（全解在这里），但起步只需要其中 2–3 个。先跑起来，其它都是可选微调。

变量必须？Supabase 路线自托管路线
MOYI_DB_URL
别名 SUPABASE_URL		必填项目地址 https://xxxx.supabase.coPostgREST 地址 http://…:3000
MOYI_DB_TOKEN
别名 SUPABASE_KEY		必填service_role key（不是 anon）任意非空串（除非 PostgREST 开了 JWT）
MOYI_CODE
别名 MASTER_CODE		建议注册 master（掌柜）的口令。不设则没人能成为 master——安全默认，但你将无法在管理台里管别的 Agent。
MOYI_DB_BACKEND可省不填时按 URL 自动识别（*.supabase.co → supabase）。识别规则见 环境自动识别。

两个几乎人人会踩的坑

① URL 漏了 http://：启动自检照样通过，但每个请求都会 500。
② Supabase 填了 anon key：因为 RLS 只放行 service_role，anon key 会让每条读静默返回 0 行、不报错，表现成「记忆凭空消失」。
这两条在 故障排查 里都有对应症状。

布尔开关还有两套相反写法（MOYI_DB_SEARCH 要 1，MOYI_DECAY 要 0），详见 环境变量 · 布尔约定。新手阶段先别碰这些，用默认值即可。

五、能部署到哪些平台

墨忆本体是一个 Node HTTP 服务，能跑在长驻进程（服务器、Docker）和无状态平台（Vercel、Cloudflare）上。但「能跑」不等于「功能一样」——限速和审计这类依赖进程内存的能力，在无状态平台上会退化。完整对比在 部署路径 那页，这里先给结论：

平台支持一句话
Docker / 裸 Node / 服务器完整长驻进程，限速/审计都有效。首选。
Vercel Serverless可用·有退化API 与管理台能用；限速每实例独立、多实例可绕过。
Cloudflare Workers / Pages可用·仅付费版代码路径已实现并本地测试；免费版 CPU 上限跑不动口令哈希，必须付费版。详见 部署 · Cloudflare。
GitHub Pages仅文档站Pages 是纯静态托管，跑不了 Node，只能托管这份文档，不能托管墨忆本身。见 文档站上线 Pages。
