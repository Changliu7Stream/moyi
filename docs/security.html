安全机制

这一页逐项讲墨忆的安全实现与为什么这么做。每条给 file:line，方便对照代码。设计取向是：零依赖下能做的全做，做不到的写清楚而不是假装没有。

口令哈希：scrypt

管理员口令用 Node 内置 crypto.scrypt，不引入 bcrypt（零依赖选型）。参数（lib/console.js:28）：

参数值说明
N16384CPU/内存代价，2^14
r8内存块大小因子
p1并行度
keylen32输出字节数
maxmemMath.max(64*1024*1024, 128*N*r*p*2)Node 默认上限太紧，N=16384 会直接抛「missing error」，必须显式放宽（lib/console.js:30,36）

自描述哈希格式

scrypt$16384$8$1$<salt_b64>$<hash_b64>

六段用 $ 分隔（lib/console.js:41-46）：算法名、N、r、p、salt（16 字节 base64）、派生键（32 字节 base64）。参数随哈希一起存，将来调参不必重算全库——老哈希按老参数验，新哈希按新参数生。

timingSafeEqual 对齐处理

验证时不能直接 return got === want——字符串比较会在第一个不同字符处提前返回，攻击者据此逐字节猜出哈希。必须用 crypto.timingSafeEqual，且两个 Buffer 长度必须相同。

问题：如果存下来的哈希格式被篡改（比如换了一个 keylen），got 和 want 长度不同。直接 return false 会让「哈希长度」变成侧信道。所以代码先补齐到相同长度再比（lib/console.js:66-74）：

if (got.length !== want.length) {
  const pad = want.length - got.length;
  got = pad > 0
    ? Buffer.concat([got, Buffer.alloc(pad)], want.length)
    : got.subarray(0, want.length);
}
return crypto.timingSafeEqual(got, want);

结果一样是 false，但分支形态一致，计时器看不出差别。

API Key：sha256 存储

Agent 密钥形态：moyi_ + 16 字节 hex（lib/moyi.js:99）。库里只存 sha256(key)（lib/moyi.js:100），认证时算请求里 key 的哈希再查表（lib/moyi.js:262-266）。

master 的部分唯一索引例外：agents_api_key_hash_idx 是 UNIQUE WHERE (role <> 'master')——master 的哈希不强制唯一。原因：master 由 MOYI_CODE 口令注册，理论上同一口令可以注册多个 master（虽然罕见），强制唯一会让第二个 master 注册静默失败。

会话：不透明 token + 服务端存哈希

会话 token 是 crypto.randomBytes(32).toString('base64url')（lib/console.js:100-102），库里只存 sha256(token)（lib/console.js:103-105）。不用自签 JWT——那种做不到退出即失效，改密码也不会踢掉旧会话。

session_version 整账号作废

admins 表有 session_version 列，admin_sessions 表也有。登录时把当前版本写进会话行；验证会话时比对两者，不一致即作废（lib/console.js:116-120）。

改口令时 session_version + 1（lib/moyi.js:824-826），旧会话版本号对不上，全部失效——这就是「没有吊销列表也能退出所有设备」的实现。停用账号时把 session_version 推到 Date.now()（lib/moyi.js:898），效果相同。

改口令轮换本 token

改口令成功后，响应里带新的 Set-Cookie（lib/moyi.js:828-831）——旧会话全废，但当前浏览器立刻拿到新 token，不必重新登录。

CSRF 双层防护

控制台写操作（POST/PATCH/DELETE）要求两样东西同时满足：

  1. Cookie SameSite=Lax（lib/console.js:155）：跨站 POST/表单不带 Cookie，挡住最常见的 CSRF 形态（跨站表单提交）。之所以不是 Strict：MCP 浏览器授权要求客户端拉起系统浏览器顶层导航到 /api/oauth/authorize，Strict 会在这一跳把会话 Cookie 拦掉，管理员就成了未登录。Lax 只放行「跨站顶层 GET」，而墨忆的 GET 全部只读
  2. X-Moyi-Console: 1 头（lib/moyi.js:633-638）：跨站 fetch 发不出自定义头（会被 CORS 预检拦住），跨站 <form> 也发不出自定义头

两道独立的门，不依赖任何一条假设。即使 SameSite=Lax 在某些浏览器版本有兼容问题，第二层头检查仍然挡得住。

为什么自定义头能防 CSRF

浏览器的同源策略 + CORS 预检机制规定：跨站 fetch 若要带自定义头，必须先发 OPTIONS 预检请求，服务端显式放行才能继续。墨忆的 CORS 白名单（lib/moyi.js:575-585）默认只放行 localhost:3906 与 MOYI_ALLOWED_ORIGINS 里显式列出的源，攻击者的 evil.com 不在白名单里，预检直接被拒，自定义头发不过去。

Cookie 属性与 X-Forwarded-Proto

Set-Cookie 的确切属性串（lib/console.js:146-155）：

moyi_session=<token>; Path=/; HttpOnly; SameSite=Lax; Max-Age=<seconds>[; Secure]

Secure 标志由 X-Forwarded-Proto: https 决定（lib/console.js:147-148）。墨忆自己不听 443，HTTPS 总是由反向代理终结，所以只能从代理传进来的头里判断。代理链可能拼成 x-forwarded-proto: https, http，取第一段（最外层、用户实际看到的协议）。

代理不传这个头 → Cookie 永远不带 Secure

后果是明文链路上会话 token 可被嗅探重放。自查：登录后看响应头 Set-Cookie 末尾有没有 ; Secure。没有就说明代理没正确传 X-Forwarded-Proto。配置详见HTTPS 与反向代理。

限速：三套独立 key 空间

限速按「调用方标识 + 动作」分桶，三套独立的 key 前缀（lib/audit.js:141,143,175 + lib/moyi.js:252,254）：

前缀用途窗口默认限额
reg:h:注册（每小时）1 小时10
reg:d:注册（每天）1 天30
auth:Agent 认证失败15 分钟30
adminauth:管理台口令失败15 分钟10

为什么分开：Agent 忘了 key 和管理员忘了口令是两件事，不应该互相锁对方。一个计数器管所有，一个人试错会把全场锁掉。

只计失败（lib/audit.js:149-171）：成功请求一律先放行、成功后清零。早期版本把所有认证请求都计进去，结果正常用户半小时就被自己锁在门外，npm test 也会触发 429。

调用方标识取 X-Forwarded-For 第一跳的 sha256 前 16 位（lib/audit.js:125-131），不落明文 IP。代理不传 XFF 时退回 socket.remoteAddress——在反代后面这个地址永远是代理自己，于是全体用户共享一个桶（详见环境自动识别）。

注册闸门与 master_code 放行

注册是公开接口（领钥匙的唯一入口），不能关掉，只能限速。但实例可以关掉自助注册（open_register=0），此时只有带对 MOYI_CODE 的请求才能进来（lib/moyi.js:1114-1130）——否则关掉注册等于把管理员自己锁在门外。

引导页 CAS

引导安装页用 settings 表里一行 setup_locked 做一次性写锁。PostgREST 的 resolution=ignore-duplicates 在行已存在时返回空 representation，据此判断「有人比我先按下了安装按钮」（lib/console.js:199-209）。两个人同时点安装，只有一个能写进去，另一个收到 409 并回滚刚建的管理员——绝不留下「建了管理员但没落锁」的中间态。

setup_locked 删除即重开（高危）

删掉 setup_locked 这一行就重新打开了安装入口

任何能写库的人都能给自己造一个超管。所以这条要当作高危操作对待。恢复流程见 SECURITY-MIGRATION.md。

全局记忆：隐私边界不是权限边界

全局记忆打开后，读作用域扩到全库（readFilter 返回空，lib/moyi.js:191-193），但写、去重合并、删除、衰减落库、访问计数一律仍锁在自己的 agent_id 上（lib/moyi.js:202，OWN_SCOPE）。

403 vs 404 不对称

全局模式下 PATCH/DELETE 他人的记忆回 403（存在但你不能动）；严格模式下回 404（不存在）。这个不对称是刻意的：严格模式下做一次「无归属探测」会把状态码变成跨 agent 的存在性探针——攻击者猜一个 id，403 表示存在、404 表示不存在。全局模式下调用方本来就看得见这条记忆（读放宽），所以回 403 更诚实。（lib/moyi.js:1498-1509）

access_count 只涨自己

全局模式下 A 读 B 的记忆，不代 B 记访问数——否则 A 反复读 B 的记忆就等于 A 在给 B 的记忆续命，那是越权写（lib/moyi.js:1492-1495）。

settings 白名单 + BOOTSTRAP_ONLY

PATCH /api/console/settings 只接受白名单里的键（lib/console.js:162）：instance_name、global_memory、open_register。杜绝客户端写进任意配置。

setup_locked 属于 BOOTSTRAP_ONLY（lib/console.js:164）：引导安装阶段能改，之后锁死。避免把已经建好的实例改回未初始化状态。

numEnv 的 NaN 防护

多处环境变量走 Number() 解析。一旦变量设了但不是数字（MOYI_W_VEC=0.7d、半衰期手滑带上单位），Number('0.7d') 得 NaN，而 NaN 会把整条运算链染成 NaN——服务照常启动、日志一声不响、接口照回 200，只是所有相关性都废了。

lib/numenv.js 在解析层拦住：解析失败回默认值，同时 stderr 警告一次（lib/numenv.js:40-55）。

CORS 默认白名单

白名单逻辑在 lib/moyi.js:575-585。请求不带 Origin 头时直接返回 null（同源请求本就不需要 CORS 头，浏览器不会拦），带了的只有下面这些放行：

  • http://localhost:3906
  • http://127.0.0.1:3906
  • MOYI_ALLOWED_ORIGINS 里显式列出的源（逗号分隔）

设 MOYI_ALLOWED_ORIGINS=* 会放行任何源——任何网页都能在浏览器里拿用户的 key 打这个 API。生产环境务必显式列出可信源。

审计 ring buffer 与脱敏

审计日志在进程内存里，环形缓冲，容量 MOYI_AUDIT_CAPACITY（默认 2000，lib/audit.js:17）。单条约 200B，最坏情况 <1MB，不会因为长期运行而涨。

写入前脱敏（lib/audit.js:44-61）：

  • 键名匹配 SECRETISH 正则（api_key|token|secret|password|master_code|authorization）→ 值替换为 «redacted»
  • 值匹配 moyi_[0-9a-f]{8,} → 截断为 moyi_xxx…(redacted)

内存态、重启即失的边界

刻意不落盘。墨忆要能在 Vercel 这类无状态函数环境里跑，落盘的日志在实例回收时就没了，写文件反而制造「以为有留痕」的错觉。真要做合规级留痕，应该往独立的 append-only 存储写。响应里固定带一句 warning 说明它是易失的（lib/moyi.js:1402）。

它刻意不做什么

写清楚做不到的事，比列一堆待办更有用：

功能现状为什么
图形验证码无零依赖选型，不引入第三方验证码服务
邮箱/短信通知无不依赖任何通知渠道
第三方 OAuth无仅用户名+口令
口令找回自助通道无忘了口令只能手工改库（见 SECURITY-MIGRATION.md）。一个能远程改管理员口令的接口本身就是最大的攻击面，刻意比「点个重置链接」麻烦
IP 自动拉黑无仅限速（滑动窗口计数），无永久封禁。要可靠封禁请放反代或防火墙
登录日志持久化无审计日志在进程内存，实例重启即失
注销流程无Agent 只能由 master 或超管删除，管理员只能由超管删除

这些是取舍而非遗漏。墨忆的定位是零依赖的记忆中间件，不是完整的用户管理系统。需要这些功能的话，请在反代层或外部网关补上。
