开始 / Quickstart

十分钟跑通

三条路径，每条都从「机器上什么都没装」走到「能存第一条记忆」。挑一条跟到底就行，不要混着来。第一次接触墨忆、想先搞懂要准备什么，先看 部署前必看；要部署到 Vercel / Cloudflare 这类平台，去 四条部署路径。

A · Docker 自托管全栈Postgres + PostgREST + 墨忆，数据在自己手里。 B · Docker 连 Supabase只起墨忆一个容器，数据库托管。 C · 裸跑 Node不装 Docker，直接 node server.js。

三条路径最后都会落到同一个地方：浏览器打开 /console，第一次访问会进引导安装页——立第一位管理员，这一步只出现一次，落库后引导页永久封存（详见 部署详解）。

A · Docker 自托管全栈

前提：已装 Docker 与 Docker Compose v2。整条栈由三个容器组成——Postgres（带 pgvector）、PostgREST、墨忆。数据卷 pgdata 第一次起容器时由镜像初始化脚本建表，之后重启不会重跑。

# 1. 拷一份配置模板，至少填 MOYI_PG_PASSWORD 与 MOYI_CODE
cp .env.example .env

# 2. 起栈（--profile local 选本地栈）
docker compose --profile local up -d --build

# 3. 等 postgres 健康检查过（约 10–20 秒）
docker compose ps

预期 docker compose ps 里 postgres 状态为 healthy，postgrest 与 moyi-local 为 running。

验证服务起来了：

curl -s http://localhost:3906/status | head -c 200
# 期望返回 {"ok":true,...} 或类似 200 响应；404 也算服务活着

curl -s http://localhost:3906/api/console/status
# 期望 {"needs_setup":true,"db_ready":true,...}

首次访问 http://localhost:3906/console 会进引导安装页。填完管理员用户名与口令后，立刻在面板里创建一个 Agent，面板会一次性显示 API Key（关掉就看不到了，只能再「重置密钥」）。

拿 Key 写第一条记忆：

curl -X POST http://localhost:3906/api/memories \
  -H "X-Moyi-Key: moyi_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"content":"我的生日是 3 月 8 日","importance":"high"}'
# 期望 201，返回里带 id、embedding、created_at

curl -X POST http://localhost:3906/api/memories/search \
  -H "X-Moyi-Key: moyi_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"query":"生日"}'
# 期望 results 数组里能看到刚才那条，search_backend 默认是 "scan"

如果想打开数据库端近邻检索，把 MOYI_DB_SEARCH=1 加进 data/moyi-env/moyi.env 并重启墨忆容器。但先回填历史向量——下推路径只覆盖已有向量的行，详见 故障排查。

B · Docker 连 Supabase

前提：已有 Supabase 项目，且已经在 SQL Editor 里按顺序执行过 sql/00-schema.sql 与 sql/vector-search.sql（前者建表，后者开 RLS 且只放行 service_role，详见 部署详解）。

# 1. 准备挂载目录，凭据只能从这里读
mkdir -p data/moyi-env
cat > data/moyi-env/moyi.env <<'EOF'
MOYI_DB_BACKEND=supabase
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_KEY=<service_role key，不是 anon key>
MOYI_CODE=<你自己想的长随机串>
EOF
chmod 600 data/moyi-env/moyi.env

# 2. 起栈
docker compose --profile cloud up -d --build

验证：

curl -s http://localhost:3906/api/console/status
# db_ready:true, needs_setup:true

后续步骤（引导安装、创建 Agent、写第一条记忆）与 A 完全一致。

不要把 anon key 配到服务端

sql/vector-search.sql 的 RLS 策略只放行 service_role。把 anon key 配到 SUPABASE_KEY，服务层会把空数组当成「没有记忆」——数据凭空消失且不报错。这是本项目最常见的错误配置。

C · 裸跑 Node

前提：Node ≥ 18。零运行时依赖，npm install 都不需要。

# 1. 拷配置并填写
cp .env.example .env.local
# 自托管：MOYI_DB_URL / MOYI_DB_TOKEN / MOYI_CODE
# Supabase：MOYI_DB_BACKEND=supabase + SUPABASE_URL / SUPABASE_KEY / MOYI_CODE

# 2. 初始化数据库（二选一）
#   Supabase：后台 → SQL Editor → 依次执行 sql/00-schema.sql 再 sql/vector-search.sql
#   自托管：psql -d moyi -f sql/00-schema.sql && psql -d moyi -f docker/init/10-roles.sql

# 3. 启动
node server.js

启动横幅会告诉你缺什么：

  墨忆 v3.3  Agent Memory Layer
  ────────────────────────────
  服务: http://localhost:3906
  管理台: http://localhost:3906/console（首次访问会进入引导安装，装完即封存）
  存储: PostgREST（自托管/兼容协议）
  状态: 运行中

如果看到 ⚠ 缺少环境变量: MOYI_DB_URL，所有 API 都会 500，先解决这个。如果看到 ⓘ 未设置 MOYI_CODE，任何人都无法注册为 master，服务能跑但没人能当掌柜——详见 故障排查。

验证与写入同 A。端口用 MOYI_PORT 改，绑定地址用 MOYI_HOST 改（默认 0.0.0.0）。

下一步

跑通之后，通常会接着做三件事：

  • 把墨忆挂到反向代理后面，强制 HTTPS——HTTPS 与反向代理 把 X-Forwarded-Proto 为什么必须传讲透了。
  • 接 embedding provider，让「语义检索」名副其实——推荐 BGE（中文强）：MOYI_EMBED_URL + MOYI_EMBED_KEY + MOYI_EMBED_MODEL + MOYI_EMBED_DIM（=模型输出维度，如 bge-large=1024），并把数据库列改成同维度，接完必须重建列并回填一次历史记忆。详见 改向量维度。
  • 让 MCP 客户端连上来：两种传输形态任选——stdio 走本机 mcp-server.js，HTTP 直连 /api/mcp 用 Bearer 鉴权免装 Node。配置片段在管理台 Agent 页创建/重置 Key 后直接给出，同时展示两种形态供粘贴。
