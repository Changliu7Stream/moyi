环境变量全解

这一页把墨忆认的每一个变量都摊开讲：它是什么意思、默认值多少、有没有边界、怎么写、写错了会怎样。变量按用途分成 11 组，你可以只跳到关心的那组。

先记两条铁律

一、真实凭据绝不进仓库。不要写进 Dockerfile、docker-compose.yml 的 environment、或前端包。任何进过公开仓库的 key 都视为已泄露，必须轮换。

二、数据库连接信息只能用环境变量配，管理台里没有这个入口。不是没做，是刻意不做——网页若能改后端地址，一次 XSS 就能把整个实例的记忆流到攻击者的库。详见管理台。

必须性总览：先分四档

下面把全部变量按「非配不可的程度」分四档。第一次部署，你只需要碰「必填」和「建议」两档，其余一律不动（默认值已经过实测校准）。

档位变量不配会怎样
必填
二选一即可		MOYI_DB_URL（或别名 SUPABASE_URL）
MOYI_DB_TOKEN（或别名 SUPABASE_KEY）		缺任一个，启动横幅报「缺少环境变量」，且每个 API 请求都回 500。
建议MOYI_CODE不设，服务照常跑，但没人能注册成 master（安全默认）——你将无法在管理台管别的 Agent。
条件必填MOYI_PG_PASSWORD（仅 --profile local 自托管栈）只有 Docker 自托管那条路要填；走 Supabase 或裸连外部 PostgREST 的可完全忽略。
全部可选下面第 4–11 组的所有检索权重、去重阈值、衰减、限速、审计、网络、embedding provider 等不设就用默认值。默认值经 test/dedupe-calibration.js 校准，非必要别改。

最少只需三个值

把 MOYI_DB_URL + MOYI_DB_TOKEN + MOYI_CODE 三个填上，墨忆就能跑完「引导安装 → 建 Agent → 存第一条记忆 → 语义检索」全流程。MOYI_DB_BACKEND 不填也行——它按 URL 自动识别（环境自动识别）。想快速照做，去 部署前必看。

三个注入渠道，谁先谁后

同一个变量可能从三处来，墨忆按下面的顺序取，先到先得，已设置的不被覆盖：

渠道怎么生效优先级适用
真实进程环境shell export、docker run -e、平台面板最高所有部署
.env.localserver.js 启动时逐行解析，仅当变量未设置时才注入次之本地裸跑
容器挂载目录docker-entrypoint.sh 读 /data/moyi-env/*.env，同样先到先得次之Docker

「先到先得」的陷阱

如果你 shell 里恰好 export 过一个同名变量（哪怕是很久以前、别的用途），.env.local 里的值就不会生效。本地调环境时若发现改了文件没反应，先用 env | grep MOYI 看是不是被进程环境抢先占了。

.env.local 的解析器只认 KEY=VALUE、去两端成对引号、跳过 # 注释——它不支持 export 前缀、不支持变量插值、不支持多行值。要复杂语义就交给真实的 shell 或平台去配。

⚠️ 布尔约定不统一：两个开关的判法相反

这是最容易踩的一处，因为两个「开关」写法长得一样、语义却相反，而且是历史成因，没有统一：

变量判定写法默认「开」需要填「关」需要填
MOYI_DB_SEARCH=== '1'关（走扫描）必须恰好是 1任何其它值都算关，包括 true
MOYI_DECAY!== '0'开任何非 0 值都算开，包括空串、false必须恰好是 0

具体后果

MOYI_DB_SEARCH=true → 不会开启数据库检索下推（它要的是字面量 1），你会继续用服务层扫描，且完全不知道配置没生效。
MOYI_DECAY=false → 不会关闭衰减（它只在恰好等于 0 时才关），衰减照跑。
正确写法：开下推 MOYI_DB_SEARCH=1；关衰减 MOYI_DECAY=0。

数值解析的 NaN 陷阱（v3.3.0 已加固）

很多数值变量早期写成 Number(process.env.X || 默认)。这个写法只在「变量没设置」时安全：一旦你设了一个不是纯数字的值，Number('90天') 得到 NaN，而 NaN 会把整条运算链染坏。

最典型的是衰减。半衰期写错一个字符，链路是：HALFLIFE=NaN → vitality = exp(-age/NaN) = NaN → decayFactor = NaN → 检索融合分 score × NaN = NaN → JSON 序列化后所有 score 字段变成 null。服务照常启动、日志一声不响、接口回 200，只是每一条检索结果的相关性都废了。根因是一个错字，排查却几乎无从下手。

现在这些 Number() 点位统一走 lib/numenv.js 的 numEnv()：值解析不出有限数字时回退默认值，并在 stderr 明确喊一声。实测：

$ MOYI_DECAY_HALFLIFE=abc node -e "…vitality…"
[moyi] MOYI_DECAY_HALFLIFE 的值 "abc" 不是有效数字，已改用默认值 90。
HALFLIFE_DAYS = 90   # 不再是 NaN，检索分数不再被污染

哪些点位改了

衰减半衰期、遗忘门槛、去重四阈值、检索权重、DB 召回门槛、向量维度。至于 parseInt(x,10) || 默认 那一类（限速、扫描上限、审计容量、会话天数），parseInt 出 NaN 本就会被 || 右侧接住，不存在 NaN 泄漏，故未改动其语义。

第 1 组 · 存储后端（必填其一）

这一组决定「墨忆认自己是哪种环境」，也是环境自动识别那页的核心。先理解一件事：墨忆不认识「数据库」，只认识「PostgREST 协议的 HTTP 接口」。所以自托管的 PostgREST 与 Supabase 托管的 PostgREST 可互换，代码一行不改。

MOYI_DB_BACKEND 可选

默认 postgrest　解析 字符串，.toLowerCase()

取值 postgrest（自托管原生 PG + PostgREST）或 supabase（托管）。不设置时按 URL 主机名推断：命中 *.supabase.co / *.supabase.in 判为 supabase。它主要影响「错误消息提示哪个变量名」和路径前缀推断，不改变协议本身。

MOYI_DB_URL 必填其一

默认 空　别名 SUPABASE_URL（本变量优先）

PostgREST 基址。自托管通常是 http://<host>:3000（挂根路径、无 /rest/v1）；Supabase 是 https://<proj>.supabase.co。必须带 scheme：漏了 http:// 时启动自检照样通过（它只查变量是否设过、不校验格式），但每个打库请求都会被 fetch 以非法 URL 拒绝、回 500。这是真实踩过的坑。

MOYI_DB_TOKEN 必填其一

默认 空　别名 SUPABASE_KEY > SUPABASE_ANON_KEY

PostgREST 的 Bearer 令牌。自托管若没给 PostgREST 配 PGRST_JWT_SECRET，这里填任意非空串即可（会被忽略，只要非空）；给了 JWT 则用 node scripts/gen-jwt.js 签发。Supabase 路线填 service_role key（仅服务端，绝不下发浏览器）。

MOYI_DB_PREFIX 可选

默认 自动推断　覆盖 显式设置后不再推断

REST 路径前缀。留空则按 URL 推：*.supabase.co→/rest/v1，其余→空。只在你用了反向代理、额外加了前缀时才显式设。注意：如果 URL 里已经写了 /rest/v1，推断逻辑不会再追加（避免 /rest/v1/rest/v1 直接 404）。

仅 --profile local 那条路需要。走 Supabase 或已有外部 PostgREST 的可整组忽略。

变量含义默认 / 边界备注

第 3 组 · 掌柜口令

MOYI_CODE 可选　（别名 MASTER_CODE，本变量优先）

默认 空 = 无人能成为 master（安全默认）

设置后，注册时带上此口令的 Agent 获得 master 角色，可管理其他 Agent、回填向量、查审计日志。不设则任何人注册都只是普通 agent。启动横幅会提示「未设置 MOYI_CODE，任何人都无法注册为 master」——这是提醒不是报错。用足够长的随机串。

第 4 组 · embedding provider

不配置时退回内置本地特征哈希向量：零依赖、离线可用，但语义能力有限，「换个说法」的召回明显弱于真实模型。支持任何 OpenAI 兼容的 /v1/embeddings。

变量含义默认关键点
MOYI_EMBED_URLprovider 的 embeddings 端点空=本地模式与 KEY 都非空才切到模型模式
MOYI_EMBED_KEYprovider 密钥空仅服务端持有
MOYI_EMBED_MODEL模型名text-embedding-3-small见下方兼容示例
MOYI_EMBED_DIM向量维度384必须等于 provider 模型输出维度，且与数据库 memories.embedding 列的 vector(<dim>) 一致（见下）
MOYI_EMBED_SEND_DIM是否向 provider 发 dimensions 参数空=不发多数 BGE / 自建部署不接受该参数，留空即可；OpenAI text-embedding-3 要截断维度时设 1

维度可改，但三处必须对齐 + 换维度/换模型后必须全量回填

维度不再写死 384：MOYI_EMBED_DIM（服务端）、sql/*.sql 里的「维度常量」v_dim（数据库列 vector(<dim>)）两处必须取同一个值；对不上时写入会被拒并静默降级本地向量。不同模型/维度的向量不在同一空间——换 MOYI_EMBED_MODEL、换 provider 或改维度后，先用新维度重建 embedding 列（见 数据库 · 改维度），再跑一次 POST /api/admin/backfill-embeddings（master 权限，带 {"overwrite": true}）重刷全库，否则检索会新旧混叠、结果失真。

常见兼容端点：BGE（中文语义强，推荐）如硅基流动 api.siliconflow.cn/v1/embeddings —— BAAI/bge-small-zh-v1.5（384）、BAAI/bge-base-zh-v1.5（768）、BAAI/bge-large-zh-v1.5 / BAAI/bge-m3（1024），把 MOYI_EMBED_DIM 与数据库列改成对应维度即可；OpenAI api.openai.com/v1/embeddings（text-embedding-3-small=1536，配 MOYI_EMBED_SEND_DIM=1 可截断）；本地 Ollama 127.0.0.1:11434/v1/embeddings（nomic-embed-text=768）。

第 5 组 · 检索

变量含义默认 / 边界写错会怎样
MOYI_W_VEC语义分权重0.7两者之和不强制为 1；只影响相对排序。numEnv 保证不会是 NaN
MOYI_W_KW字面/关键词权重0.3
MOYI_SCAN_LIMIT扫描模式一次拉取上限1000，钳制 [200, 5000]parseInt；填 90 会被抬到 200，填 99999 压到 5000。仅 scan 模式有意义
MOYI_DB_SEARCH检索下推到数据库关；须 === '1'前提：已建 match_memories 且记忆已向量化。RPC 缺失自动退回 scan，并在响应 search_backend 里如实标注
MOYI_DB_MIN_SIMDB 端最低相似度门槛0.05，钳制 [0,1]调高召回变少但更准；调太低会捞进噪声

第 6 组 · 语义去重阈值

默认值已用 test/dedupe-calibration.js 的实测样本校准，非必要不要改。四者都是 0–1 的小数，经 numEnv 解析（写坏回默认）。

变量含义默认
MOYI_DEDUPE_VEC模型模式下判「语义重复」的向量余弦门槛0.90
MOYI_DEDUPE_VEC_LOCAL本地哈希模式下的向量门槛（区分度不足，故放低）0.70
MOYI_DEDUPE_LEX字面重合判重门槛0.88
MOYI_DEDUPE_LEX_PROVIDER模型模式下叠加的字面重合下限0.60

为什么本地阈值和模型不同：本地哈希向量的区分度不够（实测「改生日」的 cos 相似度 0.97 竟高于「语序调整」的 0.91），若沿用模型的 0.90 会漏判，所以本地模式把向量门槛放到 0.70、把字面门槛提到 0.88，并叠加事实冲突护栏。

第 7 组 · 记忆衰减与遗忘

活力公式：​vitality = max( exp(-(年龄天 / (1+访问次数)) / 半衰期), 重要性地板 )。访问次数按「复习次数」缩小有效年龄——被反复用到的记忆衰减更慢。

变量含义默认 / 边界说明
MOYI_DECAY_HALFLIFE半衰期（天）90，下界 7调小=忘得快。低于 7 会被抬到 7。numEnv 解析
MOYI_DECAY衰减总开关开；仅 0 关关掉后检索排序不受时效影响
MOYI_FORGET_AFTER_DAYS进入遗忘候选的最小年龄180，下界 30numEnv 解析
MOYI_FORGET_MAX_ACCESS遗忘候选的访问次数上限1，下界 0访问次数≤此值才算「几乎没人用」

遗忘永不自动执行

即便同时满足「low + 超期 + 几乎没访问」，也只出现在 /decay/preview 的 would_forget 候选清单里。真要删，得逐条 DELETE /api/memories/:id。降级（medium→low）需 POST /decay/apply?confirm，且 high 永不自动降级。这是防止误删用户资产的硬约束。

MOYI_REGISTER_PER_HOUR注册限速 / 小时10，下界 1

第 10 组 · 管理台

引导安装页 /console、API /api/console/* 的行为参数。详见引导安装与管理台。

变量含义默认 / 边界要点

第 11 组 · 网络

变量含义默认
MOYI_ALLOWED_ORIGINS允许跨域访问 API 的前端来源，逗号分隔空（=仅同源 + localhost:3906/127.0.0.1:3906）
MOYI_PORT本地服务监听端口3906
MOYI_HOST本地服务绑定地址0.0.0.0

把 MOYI_ALLOWED_ORIGINS 设成 * 会重新引入 CSRF 风险

默认白名单里永远额外包含两个本地地址（写死在代码里，不随此变量清空）。设 * 等于任何网页都能在浏览器里拿用户已登录的状态打这个 API——而管理台用的正是 Cookie。生产环境按反向代理页显式列你自己的域名。

MCP Server 侧变量

mcp-server.js 是被 MCP 客户端（如 Claude Desktop）拉起的独立进程，只认两个：

变量含义默认
MOYI_API墨忆服务地址http://127.0.0.1:3906
MOYI_KEY本 Agent 的 API Key（moyi_…）空=不可用

这两个通常直接写进 MCP 客户端配置里那段 env，不必进服务端环境。管理台建 Agent 后会一次性产出可粘贴的 MCP 配置片段。

如果客户端支持远程 HTTP 形态（走 /api/mcp 这条 Streamable HTTP 端点），则完全不需要这两个变量：只需一段 URL 和 Bearer 头：

{
  "mcpServers": {
    "moyi": {
      "url": "https://<你的部署域名>/api/mcp",
      "headers": { "Authorization": "Bearer moyi_<这个 Agent 的 key>" }
    }
  }
}

鉴权、作用域、隔离规则与 stdio 完全一致——两种形态共用同一把 Key、同一套接口，可以同时配置使用。详见 Agent 页的 MCP 章节 与 API 页的 /api/mcp 条目。

配置自查清单

上线前逐条对照，尤其第 1、2 组：

  • 存储 URL 带 http:///https:// 了？token 非空了？
  • 布尔开关用的是 1/0，不是 true/false？（见上）
  • 接了 embedding？MOYI_EMBED_DIM 和数据库列维度对得上吗？换模型/维度后重建列并回填了吗？
  • MOYI_ALLOWED_ORIGINS 是具体域名，不是 *？
  • 反向代理传了 X-Forwarded-Proto？（否则会话 Cookie 不带 Secure，见 HTTPS 页）
  • 凭据只在环境变量/挂载目录里，没进 git、没进镜像层？
  • PostgREST 端口没暴露公网？（自托管栈下它等于整库含管理员哈希公开）
